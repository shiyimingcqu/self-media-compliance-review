# 视频审核工具组件

品牌在项目的「配置项目规则 / 编辑项目规则 → 视频审核规则」配置组件。两套规则属于项目，项目下全部达人共同使用；参考图也在项目内复用。添加达人只填名称和平台，不再为达人创建规则。原有文字视频规则仍可读取、编辑，也可添加组件。

## 当前提供的检查

| 组件 | 品牌配置 | 程序复核 |
|---|---|---|
| 产品露出 | 产品参考图、时间范围、完整入画、Logo可辨、遮挡条件 | 是否存在满足条件的观察区间 |
| 商标露出 | 商标图、时间范围、遮挡条件 | 目标商标在范围内是否可辨 |
| 产品镜像 | 正常方向包装图、检查范围 | 明确镜像即不符合；无方向依据或无目标产品为待确认 |
| 露出时长 | 连续与累计最短秒数、参考图 | 裁入检查范围、合并重叠区间，计算最长连续与累计时长 |
| 露出次数 | 最少次数、两次之间的最短间隔、参考图 | 连续与重叠区间去重，按约定间隔计数 |
| 禁用表达 | 每行一个词句、时间范围 | 使用VLM结合上下文的命中观察；无完整音轨不以未发现算通过 |
| 必须口播 | 每行一个必讲点、时间范围 | 每一必讲点须有对应原声音频观察；字幕不替代口播 |
| 指定动作 | 动作说明、时间范围 | 核对VLM记录的完整动作观察，模糊或剪断时待确认 |

前15秒露出、产品不得镜像、禁用表达提供快捷模板；模板里的数值仍须品牌确认。单个节点最多选择4张参考图。

## 组合规则

- AND：全部节点满足；任一不符合则不符合，其余存在未知则待确认。
- OR：任一节点符合即可；没有符合但存在未知则待确认。
- 「同一段画面同时满足」只用于AND视觉组件：取各节点合格时间区间的交集。各自通过但无共同画面时组合不符合。
- 所有配置节点都必须实际调用；OR也需要返回每个节点的结果，便于品牌追溯。
- 规则的文字说明与组件参数应保持一致。确定性参数以品牌确认的组件配置为准，不允许模型更改时间、参考图或计数阈值。

## 模型与工具的分工

完整视频及音轨与品牌参考图一起输入设置中的兼容多模态模型。没有把视频抽帧作为审核输入。

VLM按各组件的专用说明阅读完整输入，调用`check_product_presence`等LangChain StructuredTool，提交可辨识程度、方向、遮挡、原声/文字和真实时间区间。工具按品牌冻结参数做确定性运算，并在最后一个节点完成时返回该条规则的组合结果。

VLM随后可调用既有截图/有声片段工具取证。最终每条规则一个finding，规则编号、问题ID、组件结果和证据ID必须对应。模型漏掉组件、编造ID或最终结论与组合结果不一致时，报告失败且不自动重试。

组件提示词位于`backend/app/modules/workflow/component_prompts/`，共8个Markdown文件。品牌确认规则时冻结提示词内容与版本；运行时使用快照，避免后续编辑影响历史审查。

注意：这里的语义观察来自VLM，工具计算可复核，但不能独立证明VLM准确看完每一帧。`coverage_complete`是模型声称已覆盖节点的检查范围，结果始终保留`coverageVerified=false`；原片仍由品牌复核。没有引入额外的逐组件收费模型请求。

## 素材与任务边界

参考图使用单独的项目素材接口，支持静态PNG/JPEG/WebP，白底归一化为PNG，原像素保留。单张原件及归一化结果≤4MiB，单张≤1200万像素；项目最多30张。每次审核最多8张、合计≤8MiB。拒绝动画、损坏图片、跨项目引用和被修改的素材。

项目素材接口：

- `GET/POST /api/v1/projects/{projectId}/reference-images`
- `GET /api/v1/projects/{projectId}/reference-images/{id}/content`
- `GET /api/v1/workflow/video-components`

图像字节不进入数据库审核快照；快照保存素材ID、哈希和尺寸，发送前验证哈希。原有文件资产表和用途不改动。

每次最多8个检查节点，为既有12次工具调用预算保留取证空间；仍最多3轮工具和1轮最终回复。每轮请求会携带完整上下文，视频与参考图可能产生Token费用。无自动付费重试。

## 品牌复核与兼容

包含组件的必须规则须全部符合，品牌才能确认视频通过；不符合或待确认时允许退回修改。建议组件不阻断必须项验收。AI报告成功不等于品牌最终通过。

原有无组件的文字规则保持人工复核流程。新脚本或重新确认标准使旧上下文失效；参考图和组件提示词随运行记录冻结。

## 验证

后端测试覆盖参数校验、参考图上传幂等、项目归属、时间交集、OR未知状态、时长去重、次数间隔、镜像不确定、缺少音轨、必讲点遗漏、漏调用组件及必须项阻断。

集成测试通过模拟模型响应驱动完整视频输入、真实参考图附加、LangChain工具调用与FFmpeg取证；不调用收费模型。浏览器测试覆盖上传参考图、选择组件、组合条件、保存及重新打开后再保存。


## 视频规则逐行编辑

视频规则列表采用与脚本规则一致的紧凑行：序号、视频要求、判定说明、检查组件、重要性和删除操作并排显示。每个组件以标签按钮放在对应规则后，缺少必填条件时标记“待补全”；点击弹出参数编辑器，保留参考图、检查范围、阈值、词句、动作与移除功能。多个组件的 AND/OR 和“同画面”通过该行的组合按钮设置；品牌参考素材默认折叠。

这次只调整编辑展示，不变更规则保存结构和判定逻辑。浏览器验证覆盖参考图上传、两个组件配置、同画面组合、保存后重开回显、追加禁用表达及多行词句保存，全程无真实模型调用。


## 当前默认：文字规则与按需取证

视频规则默认使用与脚本一致的逐条文字编辑器，支持搜索、重要性筛选、排序、来源查看，以及“根据 Brief 生成视频规则”。生成使用独立解构模型，结果进入草稿，品牌核对保存后生效，不自动发起视频审核。编辑和保存保留规则的 params（品牌/产品名、词句、数值阈值）。

视频审核对照完整输入逐条给出判断；具体画面问题按需截图，口播/剧情等问题按需保留有声上下文。同一事实支持多个规则时可复用同次调用证据；缺失项说明检查范围，不强制取证。组件配置迁入默认折叠的“高级组件配置（可选）”。已有组件条件仍会执行，界面显式提醒，不自动删改历史配置。

浏览器验证覆盖：视频范围的AI候选生成（固定响应，无真实模型调用）、脚本规则隔离、具体事实参数保存及重载、旧组件保存与回显、已有生成结果本地恢复。
