# 根据平台生成 Brief 规则

项目运行时的平台规则包位于 `backend/app/modules/workflow/platform_skills/`，由服务端加载。这不是给开发助手安装的技能，也不需要额外模型或新增计费调用。

## 选择和组合

每次生成仍调用原有 Brief 解构模型一次。输入组合为通用八维/当前材料生成提示词、Brief 事实及出处、平台规则包、当前阶段边界。

服务端以项目的 `platforms_json` 选平台包，不能由 Brief 中的文本切换。小红书、抖音分别维护 `SKILL.md`、`sources.json` 与 `cases.json`。其他平台使用通用边界，不借用已有平台政策。

| 入口 | 材料类型 | 检查阶段 |
| --- | --- | --- |
| 脚本规则 | 台词、字幕设计和分镜安排 | 拍摄前安排 |
| 视频规则 | 提交音视频及适用封面 | 内容验收 |
| 图文规则 | 封面、有序配图、标题正文 | 内容验收 |

一个项目若配置多个平台，目前仍共用一套保存规则，因此生成采用共同适用口径，不擅自选主平台。专属要求应进入待确认提示；代码略过标题中明确标识为其他平台或仅限某个平台的专属候选。本次没有增加按达人平台执行不同规则的存储机制。

## 内容边界

- 图文图片数、Live 图不能换成视频次数或秒数。
- 脚本安排不等于实际成片完成。前15秒出现，不等于持续15秒。
- 发布配文中的标签不强制成为口播。片中明确要求展示话题的，仍可检查。
- 图文正文是本次提交内容，可以核对；报备、上线排期、发布标记、评论维护和留存属于发布运营，不成为内容硬门槛。
- 创作经验默认建议，不冒充平台政策。通用八维和 Brief 明确要求继续生效。

生成后代码只拦截明确的跨阶段标题，不用关键词推断复杂语义或修改已保存规则。被略过的候选保存在运行结果 `excludedCandidates`，原始模型返回保留。没有适用新增图文/视频规则时保留现有草稿；脚本由代码保留八维基础模板。

## 版本和来源

运行快照 `platformSkills` 保存平台列表、材料类型、阶段、包版本和官方来源。完整组装提示词及哈希照常冻结。包版本包含通用说明、平台说明、来源元数据及固定案例的哈希。

截至2026-10-25，巨量星图官方内容管理规范正文可读；小红书蒲公英官方入口可达，但本次未取得可读正文，来源标记为 `entry_only`，不据此补造具体硬性政策。这些包不代表已实现平台全量合规检查，不会在每次生成时实时联网抓取平台规范。

修改包内容后运行固定案例及相关生成回归；平台政策需要人工核对官方正文、适用范围和更新时间。历史记录不重新加载新包；本地恢复使用原快照平台上下文，不发起模型请求。

## 品牌审稿四组优先级

两个平台包共同加载 `brand-priorities.md`，各自的 `SKILL.md` 再细化平台重点：

1. 交付要求50%：明确必提信息、卖点准确性、产品及规格、价格和条件、用法场景、必含画面及结构、转化指引、品牌禁区。
2. 风险30%：具体虚假误导、资质授权、适用平台禁止要求、明确侮辱歧视及舆情疑点，结合原文上下文核查。
3. 品牌调性10%：默认建议；明确 VI 和固定表达要求归第一组。
4. 传播效果10%：默认建议；小红书侧重信息可信与搜索表达，抖音侧重开场、演示及信息推进。创作经验不自动成为硬门槛。

权重仅用于审稿关注顺序，不计算加权放行分数，不抵消任何必须项失败，也不替换现有八维分类、冻结编号或 JSON 输出格式。平台上下文记录 `priorityProfile`，规则包哈希包含共同优先级文件。原有运行和已保存规则不自动变化。

## 视频规则生成总则

`prompts/video-rule-generation.md` 共用于普通视频规则、分层候选及通用模板补全三种模式，由 `prompts.py` 实际加载。内容包括成片四组优先级、口播/字幕/画面核对、核心脚本一致性、产品辨认、证据边界、量化组件及当前输出契约。生成总则不注入脚本/图文生成或实际审片提示词，不追加模型调用；新内容参与提示词哈希和运行快照。

模式原有行为保留：通用模板补全仍保留六条基础检查，分层生成不覆盖基础项且候选默认关闭。具体事实和证据不能在规则生成阶段伪造，未提供的脚本细节不作为假定要求。
