# Brief 布局识别、区域 OCR 与重点汇总

当前新任务使用 `layout-crop-summary-v2`。保留旧任务原始输出、人工确认和事实卡，不自动发起真实模型调用，也不把旧结果标记为新流程已识别。

## 三个阶段

1. VLM 看原页判断 `sequential` 或 `regions`。顺序页无需坐标；多栏、独立块或表格页返回归一化到 0..1000 的矩形坐标、原行列标题、共享范围及参考/要求/背景类别。此阶段只定位，不转录和汇总。
2. 顺序页整图识读，复杂页在原始渲染图上按框实际裁图，再逐区域识读。区域 jobId 与物理页码受严格校验，框必须有正面积并在原页范围内。区域原文与所属单元格一并保存，合并格不强拆。OCR 不生成事实卡，也不写冗长画面赏析。
3. 全部识读完成后只提交一次全文重点汇总（纯文字），保留品牌、产品、核心卖点及明确的词句/拍摄/发布要求/阈值，去除目录和参考示例的冗余摘要。所有事实引文仍需在指定页连续定位，材料与阶段归属不靠关键词猜测。区域原文不自动逐条入卡。

输入图片按每批最多24张、base64后20MiB预算分批；独立批次最多2个并行，阶段之间有依赖，不自动重试。实际调用量由页数、复杂区域数和图片字节数决定，不能保证比旧流程固定更快；布局阶段只输出短结构，OCR只输出文字，事实全篇只汇总一次，避免此前五批各自重复生成所有字段。

## 完整性、失败与进度

`result.progress` 每个阶段开始及每批返回后落库，页面显示布局、识读、重点汇总阶段及已完成/总批数。分区 bbox、原文和原页信息保存在可追溯结果中；待核对保留真实引文或识读疑点，不因区域数量或程序容量生成逐条待办。

布局/裁图/编号错误会阻止依赖阶段。重点汇总失败时保留已成功的 OCR，单独记录 factsError；显式继续且版本、文件和配置一致时复用 OCR，仅重做重点汇总。明确“重新图文识别”仍会重新走全流程。缓存按源版本和 pipelineVersion 隔离，原始阶段响应保留，不自动重试或假称任务成功。

VLM 的框选、识读和摘要仍可能出错。坐标有效不代表覆盖原图全部内容；摘要也不等于品牌已确认，coverageVerified 始终 false。没有进行真实付费模型的性能或准确率测量前，不宣称完成实测。

## 兼容旧任务

旧 `visual-regions-v1` 任务继续按原快照解释；相关测试明确覆盖旧契约。新默认流程由独立布局/裁图/识读/汇总测试覆盖，包括像素裁切、批次预算、阶段进度、错误中止、摘要失败保留及仅重做摘要，不调用真实供应商。

## v2：真实边界与来源编号

现场复现：第20页 VLM 返回规则化的200/400/650坐标，切掉左列句首，且把右侧跨图片/视频的同一黑色底板误拆。仅验证0..1000坐标合法不足以验证边界正确。

程序从当前校验过SHA的原PDF提取轴对齐实心矩形和文字行边界，作为可选布局候选。识别后将有足够几何重合的框对齐到实际底板；相同底板中的同类区域合并，沿真实左侧行标签与上方列标题保留归属，嵌套高亮不当表头。没有底板时只补全被相交的原生文字行，不按语义猜范围。原始layout与每处调整分别留存。扫描、旋转或无原生几何的页面仍需视觉识读，不能宣称这一检查覆盖所有PDF。

汇总输出 `sourceId`，原文由程序从同页已保存的连续段落回填。模型不能自行用省略号拼接quote，未知编号会导致摘要阶段失败并保留OCR。品牌只输出一套brandEntities，减少主品牌与别名重复提交为冲突候选。不同来源的15秒和30秒要求应分别汇总，不擅自解释成相互替代。

本地第20页已按原PDF几何导出五个主体要求区及核对稿，未调用付费模型，未改写历史VLM响应，也未把旧页面结果冒充新结果。
