# 项目统一审核规则

项目详情通过「脚本规则」「图文规则」「视频规则」三个大按钮直接进入独立规则页面 `/projects/:projectId/rules?type=script|image|video`，不再打开侧栏。三类内容切换保留草稿并同步地址参数，保存后留在当前页面。脚本和图文采用紧凑列表并排展示编号、要求、判定说明、重要性和操作，支持搜索与必须/建议筛选；来源引用可展开核对。视频保留工具组件配置并压缩上下间距。页面提供保存状态与未保存离开提醒，窄屏自动换行。

图文规则单独存入 `project_image_standards`，旧客户端省略图文字段时保留已有图文规则。本次增加图文规则配置，不增加独立的图文交付审核流程。

项目代表一次品牌产品推广，例如「麦咖啡芝士浓奶铁抖音项目」。同一项目包含多个达人任务；每位达人保留自己的脚本、视频版本、AI反馈和品牌复核记录。

项目详情用「上传并解析 Brief」替代流程介绍卡片。每个项目只有一份当前 Brief，支持 PDF 文本层与 TXT 解析、原文预览及版本替换。上传和文本解析不调用收费模型；PDF 图片及扫描页面可通过「AI 图文解析」使用已配置模型识读，支持逐页原图对照，结果复用于规则生成和脚本审核。模糊、漏页或识读省略仍提示待核对。替换后旧文件和审核快照保留，解析失败保留原有当前文件，版本冲突拒绝覆盖。详见 [Brief多模态解析](BRIEF_MULTIMODAL.md)。

桌面项目详情采用一屏概览：Brief 与三类规则入口并排，压缩标题与留白，达人列表每页5位，解析原文通过预览弹窗查看。1366×768 下含未解析提示与5位达人的页面无需整页滚动；超过5位使用分页，接口10条数据拆成两个界面页，跨页保留完整列表。窄屏自然堆叠以保证可读性。

`project_current_briefs` 保存项目唯一当前来源指针。`GET/POST /api/v1/projects/{projectId}/brief` 读取或替换该指针；POST 使用文件 ID、当前 `revision` 及幂等键。历史来源继续保存在已有 Brief 来源表。升级时自动采用唯一可读来源，或项目规则已经明确确认的来源；其余多份历史资料不擅自选择。

脚本审核模型输入包含当前 Brief 的完整可读原文块、来源版本、项目脚本规则和达人脚本文字/图片，并冻结到审核快照。规则生成也读取项目当前 Brief，编辑页不再单独上传另一份文件。Brief 更新使全项目旧审核资格失效；Brief 有未解析资料时不自动授予完整验收通过资格。没有来源的历史自定义规则保留兼容，但模型会说明缺少 Brief 的限制。

品牌在项目详情「项目统一审核规则」配置两套标准：脚本审核规则、视频审核规则。均支持逐条编辑；视频规则支持检查工具组件与项目参考图。保存时由品牌确认，形成不可变的项目规则版本。达人任务按项目读取当前规则，不复制规则、不设置达人专属版本。平台范围由项目确定。

先确认项目规则，再「添加达人」。达人端上传脚本后按项目脚本规则验收，必须项全部通过才进入品牌复核；品牌通过后才能提交视频。视频按项目视频规则与已通过脚本审核，最后由品牌确认。

项目规则更新会同步影响所有未归档达人：旧审核上下文与通过资格失效，阶段回到脚本验收。脚本、视频和历史审核结果保留；已在运行的模型请求仍保留旧快照，返回结果不能获得新版本的通过资格。不同项目互不影响。

## 接口与存储

- `GET /api/v1/projects/{projectId}/standards`：当前项目规则版本、两套标准、待确认的历史候选。
- `POST /api/v1/projects/{projectId}/standards/confirm`：提交两套规则、品牌确认及当前 `revision`。版本冲突返回409；幂等键重放不会重复保存。
- `POST /api/v1/projects/{projectId}/creators`：只需 `creatorName`、`platform`；自动使用项目统一规则。

`project_standard_sets` 按项目、审核范围和版本保存冻结规则。旧 `task_standard_sets` 保留作历史，不参与当前规则读取。旧任务确认接口兼容时也会更新整个项目，不能创建达人专属规则；旧发布接口仅接受与项目一致的规则。

启动时，只把所有活跃达人均已确认且内容完全一致的历史规则提升为项目规则。存在差异、资料缺失或未确认时不自动选择；品牌可在项目规则编辑器选择历史候选作为草稿，编辑并确认。升级前应备份数据库。

## 引文核对口径
规则引用必须逐字来自所选 Brief：同一原文块内的连续片段，或**同一页多个原文块按顺序拼接后的连续片段**（忽略空白差异）。PDF 的识读文字常被拆成很多短块，模型习惯把相邻块拼成一句完整的话再引用，早期只认"单块内子串"，2026-10-22 两次脚本生成（各 6–8 条规则）就因为 2–3 条跨块引文整次失败。

现在生成阶段的修复顺序是：块内命中 → 同页另一块完整命中（换块）→ 省略号还原为该块连续原文 → 同页多块拼接命中（合并成该页连续原文，必要时把出处改到覆盖引文的首个块，并写入提示）。跨页拼接、改写原文、引用别的页仍然整次失败（`INVALID_STANDARD_SOURCE`），失败提示改为"重新生成或先改掉这几条引用"，不再引导本地重新校验——那对这类错误无效。

冻结后的规则复核与确认走同一套判定 `quote_located`，但要求引文从被引用块开始，避免把出处落在区间中间块而无法证明起点。回归测试：`backend/tests/test_citation_spans.py`（跨块合并、空白差异、跨页拒绝、改写拒绝、冻结复核），真实失败记录重放验证通过。

## 脚本生成不返回视频分层字段
`StandardRule` 同时承载视频三层配置（layer / enabled / baselineKey / presetKey / componentPlan）。strict JSON Schema 会把对象全部属性标为必填，脚本生成时模型因此被迫编出 `layer: "brief"`、`baselineKey: "product"` 这类视频字段，保存时撞上 `VIDEO_LAYER_SCOPE_INVALID`（"三层配置只适用于视频"）。此前这个 bug 被引文校验失败挡在后面，引文一修好就暴露。

现在两处收口：`json_completion` 对脚本提示词调 `prune_video_fields`，从规则对象 schema 删除这五个字段并清理不再被引用的 `$defs`；`validate_recommendation(value, blocks, scope)` 增加 scope，非视频 scope 丢弃残留字段并写一条说明，视频不受影响。前端保存脚本/图文规则时同样清洗（`withoutVideoLayers`），所以浏览器里已经带着 layer 的旧草稿也能直接保存。

## 提示分组
平台自己追加的提示（引文跨块合并、同页换块、省略号还原、忽略视频分层字段、未完整识读、仅本地重新校验）统一带 `【系统提示】` 前缀；模型写的 Brief 疑点不带前缀。前端 `RuleWarnings` 把前者收进折叠区「系统提示 N 项（引文定位 · 重新校验 · 识读完整性）」，后者用警示色逐条列出并显示条数，规则页、视频候选和发布抽屉三处一致。历史记录没有前缀，`splitWarnings` 按已知措辞兜底识别，避免老记录两组错位。

## 生成超时与等待提示
规则生成的读超时单独放宽到 600 秒（`RULE_GENERATION_READ_TIMEOUT`），事实卡提取仍是 300 秒（`RECOMMENDATION_READ_TIMEOUT`）——两者共用解构模型配置，但规则生成要输出 6–8 条带引文的规则，思考型模型常超过 5 分钟，2026-10-22 两次视频生成都卡在 300 秒被判超时，供应商是否计费未知。快照里的 `requestOptions.readTimeoutSeconds` 和超时提示文案都用这个值。

前端在生成按钮旁显示"已等待 N 分 M 秒 · 最长等待 10 分钟，切走页面不会中断"，失败时除页面内 Alert 之外再弹一次 message.error，避免错误提示落在长页面底部看不到而误以为卡死。

## 视频规则页面：档位只决定叠加到哪，列表始终是连续的一列
视频规则页不再显示"第一层/第二层/第三层"区块，规则和脚本规则同一个紧凑格式：编号、要求、判定说明、重要性、操作（上移/删除），判定说明直接在行内编辑，不再收在"提示词"弹层里；基础资料、组件按钮、量化阈值这些视频专属内容放在要求列下方。

顶部保留"基础版 / 进阶版 / 严格版"：基础版只显示默认那几条基础规则；进阶版在此基础上叠加文字规则；严格版再叠加量化检查（几秒、几次）。切换档位时更高档位的规则**保留但隐藏**，列表下方提示"N 条更高档位的规则已保留"，审核也不使用它们（`video_layers.active_rules` 按每条规则的 `videoReviewLevel` 过滤）。

AI 生成不再进候选区，直接追加到列表末尾：文字规则默认启用，量化检查因为没有组件先保持关闭，配好组件后才能启用（后端本来就要求启用的量化规则必须有 componentPlan）。同文案的规则不会重复追加，总数仍受 60 条上限约束。

审核结果页的层级标签同步从 L1/L2/L3 改为 基础检查 / 文字要求 / 量化检查。

## 验证

后端覆盖多人共享、模型输入一致、版本冲突、幂等重放、全项目资格失效、历史记录保留与历史规则迁移。浏览器覆盖项目配置、添加达人、Brief推荐、视频组件配置与两个达人共享更新。模型请求在测试中模拟，不产生供应商费用。
