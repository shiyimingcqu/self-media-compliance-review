# 脚本审核调用与报告校验

2026-10-21 格式可靠性更新见 [输出协议与恢复说明](SCRIPT_OUTPUT_RELIABILITY.md)：新调用启用原生 JSON 输出约束，使用原文 ID 引用；解析错误与字段错误分开记录。部分条目和本地格式修复候选可以显示，但不能自动通过。下列历史 `SCRIPT_REPORT_INVALID` 记录保持原状，不自动重新调用供应商。

- 脚本多模态调用保留完整 Brief、脚本文字与图片。连接超时15秒，等待返回300秒，发送 `reasoning_effort=none`，不自动重试。
- `quote` 为完整连续原文、`quote_segments` 为其中按序存在的重点片段时，核验两者后统一使用首片段与片段列表展示，不再误报 `quote segment mismatch`。伪造、倒序、与该引文无关的片段仍拒绝。整份报告未通过校验时，图片说明明确显示“报告尚未通过校验，图片说明未采纳”，不会把原始返回直接作为已确认报告展示；本地重新校验成功后图片说明随有效报告恢复。
- Brief 生成规则现在使用[独立解构模型](DECOMPOSITION_MODEL.md)，默认 `qwen3.8-flash`、`reasoning_effort=xhigh`、Temperature 0.1；历史记录的 `none` 参数保持原样。连接超时15秒、读取超时300秒、发送超时60秒。生成记录保存请求选项，超时或连接异常保存具体异常类型；不保存异常消息中的潜在凭据。旧的120秒失败记录保持原样，不会自动重发。用户应先核对供应商用量，再主动重新生成。
- 推荐引用校验仅允许确定性修复：同页恰有一个完整块包含逐字引文时重新定位；省略号两端的片段均依次存在于所引用块时，恢复其中连续的完整原文。不存在、歧义、顺序错误、改写或跨页引用仍拒绝。品牌手动保存规则的原文校验保持严格。
- 同一Brief再次图文解析后，已保存规则仍可逐字引用该Brief成功历史识读的不可变原文块；保存校验按项目、Brief来源版本、识读任务状态与块ID核对，不因最新识读任务改变而丢失历史引用。历史块只参与引用来源核验，不混入当前AI审核输入；当前审核仍使用最新有效识读。另一Brief、失败任务、伪造ID或改写的引文仍拒绝，并返回具体规则范围、编号及字段位置。规则仍需品牌主动保存，不自动更改或确认。
- 规则页「恢复上次生成（不调用AI）」调用 `POST /api/v1/projects/{projectId}/standard-recommendations/{id}/revalidate`，仅处理已保存模型输出。恢复结果创建新候选记录，保留原失败记录、原始返回和供应商请求ID；未自动确认项目规则。当前Brief或已冻结识读材料变化时拒绝套用。引用正确不证明口径合理，品牌应核对哪些要求是必须项、背景或建议。
- `PROVIDER_READ_TIMEOUT` 表示未在等待期限收到完整报告，是否计费未知；`PROVIDER_CONNECT_TIMEOUT` 表示建立连接超时。HTTP拒绝单独记录状态、脱敏错误与供应商请求ID，不再混作报告格式错误。
- 前端提交期间持续刷新状态，显示本次审核进行中，不展示上一次失败作为本次结果；已有审核处理时阻止重复提交。
- 非连续引文使用 `quote_segments` 分段显示，每段必须是脚本原文。对于模型以换行拼接的引文，只在每段真实存在且顺序一致时转换；编造、改写、错序仍然拒绝。连续的 `quote` 继续严格逐字校验，图片及规则编号校验不变。
- 失败页可展开调用诊断，查看错误码、审核ID、请求ID、报告校验原因及保留的模型返回。
- 有完整模型返回且仅格式校验失败时，可通过服务函数 `revalidate_saved_script_report` 使用原有快照本地重新校验，无供应商请求。成功时记录恢复方法、前次错误和审计事件；不会更改输入快照，也不自动作品牌通过决定。
- 审核调用成功、AI必须项验收通过、品牌确认通过是不同状态。Brief资料未完整解析时仍阻止完整验收通过，保留AI反馈供核对。
- 脚本反馈的引文校验现在逐条处理：改写、错序或无法匹配的引文保存在 `unverified_quote` / `unverified_quote_segments`，清除不可验证的文字定位，并将同一规则的反馈与必须项统一降为 `needs_confirmation`。前端显示“引文待人工核对”，不为错误引文生成高亮或连线；其他有效反馈及图片说明继续展示。此项处理不放宽 Brief 标准引用逐字且同块的要求，也不放宽规则编号、图片身份和完整覆盖校验。保存结果的本地恢复方法为 `partial_quote_evidence_v3`，不调用供应商、不改变原始响应及输入快照。
