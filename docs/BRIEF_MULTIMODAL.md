# Brief 多模态解析

项目详情的“上传并解析 Brief”先提取原文，再自动使用已保存的 VLM 识读 PDF 并同时生成事实卡，模型调用可能计费。长文档逐批调用，但不会再额外调用语言模型提取 PDF 事实卡。TXT 直接读取文字后由独立语言模型生成事实卡。需要模型支持图片输入和 JSON 输出。

PDF 每页渲染为长边 2200 像素的完整 JPEG，连同物理页码、已有文字与专用提示词提交模型；不裁切页面。整份文档不设页数上限，后台按每批最多24页、图片 Base64 总量最多20MiB自动分批调用，保留物理页码并合并结果；无需手动拆分。每批分别校验页码，任一批失败不会标记整份材料已完整读取，已返回的批次与请求 ID 保留用于诊断。解析任务后台执行，可查看处理中、成功、失败和请求 ID。300秒读取超时，不自动重试，超时不能保证供应商没有计费。

模型逐页返回转录文字、画面与布局说明、可辨认程度和具体缺口；同一回复的 facts 返回品牌、产品、卖点、必提/禁用词、发布与数值要求，每条携带页码和引文，代码合并并校验后写入事实卡。缺页、重复页、非法格式等不会解除未覆盖提示。模型标记模糊或内容省略时，该页仍为待核对；即便模型自称完整，输出承认省略也会触发完整性检查。机器判定不能证明绝对无遗漏，品牌仍需核对原件。

「查看解析内容 → 页面对照」显示页图和对应文字，可切换页码并放大原图。识读文字与原有文本合并供规则推荐使用，附带页码、来源块 ID 和识读任务 ID；规则来源可引用识读块。参考图片与营销硬性要求由提示词明确区分。

任务保留文件哈希、逐页图片哈希、模型配置版本、提示词版本、结果、供应商请求 ID 和用量，不持久化明文 Key 或 Base64 请求体。同一当前来源完整成功后直接复用；请求幂等键重放不会重复收费。部分成功允许用户主动再次解析，产生新调用。更换 Brief 后旧结果保留，不能套到新来源。

新增识读结果会使全项目已有审核资格失效，下一次脚本审核使用新增资料；历史审核输入和反馈不重写。服务重启会把未完成任务标为中断，不自动补发收费请求。

接口：

- `POST /api/v1/projects/{projectId}/brief/vision`：要求 `Idempotency-Key`，请求包含 `sourceVersionId`、`briefRevision`、`configRevision`、`allowRealCall: true`，新前端另带 `extractFacts: true` 同时生成事实卡，返回后台任务。
- `GET /api/v1/projects/{projectId}/brief`：包含最新任务、有效识读 ID、合并文字、原始及剩余未覆盖资料。
- `GET /api/v1/projects/{projectId}/brief/vision/{runId}/pages/{pageNo}`：检查项目归属、文件完整性后提供页面预览。

实现提示词位于 `backend/app/modules/workflow/prompts/brief-vision.md`；PDF 渲染依赖 `pypdfium2==5.14.0`。迁移 `W_0008_brief_visual_runs.sql` 随服务启动执行，升级前备份数据库。
