# 脚本规则生成：引用编号与八维基础模板

新逐条脚本规则使用 `script_refs_v1`，视频、图文和历史单段文字接口维持原有契约。

- 服务端从当前 Brief 的真实文本或已核对事实卡中生成稳定 `src_…` 编号，保存到运行快照的 `sourceReferences`。
- 模型只返回 `sourceRefs` 编号数组；强约束 JSON Schema 中不提供引文、原文块编号或来源验证状态的输出字段。可选择多处依据。
- 代码逐项验证出处并回填 `sourceReferences`；旧 `sourceBlockId`、`sourceQuote` 映射到第一处，兼容已有页面及接口。多处引文独立保留，不伪装成连续原文。
- 八维通用规则由代码补齐。AI 的已核对补充合并到对应维度，基础判据和必须项不被删除；额外候选保留为独立条目。只更新生成草稿，不直接改写已保存规则。
- 引用未知、跨 Brief 或无法确定的候选保留为 `citationStatus=pending`，默认停用，并保留原始模型回复。其余有效规则正常返回。品牌可在详情里核对后按自定规则采用，`citationConfirmed=true` 不代表出处已验证。
- 保存时重新校验所有实际引用。待核对候选未经品牌确认不能启用；停用项不参加脚本审核。
- 旧失败回复可通过“恢复上次生成”本地处理：仅恢复同一块中唯一、逐字存在的换行片段，使用其真实连续原文；不存在或有歧义的引用不猜测。恢复会新建派生记录，保留旧记录和原始回复，不调用模型、不自动保存项目规则。

固定响应测试覆盖多引用、未知编号、跨 Brief、旧引用恢复、八维补齐、单次调用与幂等、保存门禁及页面确认回显。测试证明结构和流程正确，不证明模型生成的要求在业务上必然合理。
