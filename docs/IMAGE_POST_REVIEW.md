# 视频入口与图文验收

## 页面与流程

- 达人端“我的合作”中，每个合作都有脚本、视频、图文三个入口，各验收页也可以直接切换。切换品牌端/达人端时保留当前验收类型。
- 视频入口支持上传完整 MP4、生成本地审核副本、发起既有完整视频审核、查看反馈、证据与调用历史。必须先完成脚本 AI 必须项验收并由品牌确认；更换脚本或规则后重新核验资格。未开放时入口仍可访问，但上传和调用被禁用并说明前置条件。
- 图文是同一合作下独立的成品通道，使用项目已保存的图文规则，不要求先通过脚本或视频。项目规则页面的“图文规则”用于配置与确认标准。
- 图文提交包含标题、正文（含话题）、按发布顺序排列的图片和可选逐图配文。第1张为封面，可上移、下移、更换与移除图片。可以只保存版本，不调用 AI；也可显式确认后保存并验收。
- 图文预览提供大图、顺序缩略图、配文、完整正文、原图下载、版本切换。反馈含每条规则结论、文字引文、图片定位、逐图说明及原始调用诊断。
- AI 必须项全部通过且材料/报告完整后，图文进入“待品牌审核”的图文复核队列。品牌核对全部文字与图片、填写意见并勾选已核对后，才能通过或退回。达人端能看到品牌意见并提交修改版。
- 内容版本不可覆盖；标题、正文、图片顺序、配文任一变化都形成新版本。新版本、图文规则、平台或 Brief 更新都会令旧验收与旧品牌决定不能用于当前内容。重审同版本也须按最新审核记录重新取得品牌确认。
- 历史版本和历史审核可以查看各自当时的规则快照与品牌决定；历史通过不代表当前版本通过。页面提供最近50个内容版本和最近50次验收、最近100条品牌决定。

## 约束与存储

- 每版1–18张静态 PNG / JPEG / WebP；每张原文件与标准化后图片均不超过4MiB，最多1200万像素，送审图片Base64合计不超过20MiB。不会静默截掉图片或正文。标题最多120字、正文最多20000字、每张配文最多500字。
- 每张图片保留原始字节和源哈希，另存经方向校正、透明背景合成的PNG审核副本；完整原图可下载。发送前核对副本SHA-256，归属精确到当前合作任务，其他任务不能引用。图片内容不会写入JSON审核快照。
- 图文素材、版本、AI审核和品牌决定分别存储在新增的 `image_post_*` 表中。现有脚本、视频、上传文件契约和历史记录不重写；旧任务可直接使用图文通道。
- 保存与审核、品牌决定各自有幂等键。重复提交同一请求不会创建重复版本/审核或重调模型；并发编辑必须匹配当前基础版本，避免覆盖他人的修改。归档任务保留历史可读，禁止新写。
- 图文调用复用已配置模型与上一轮报告可靠性协议：原生JSON输出、原文ID引用、完整响应先保存后解析、分层错误诊断、部分结果保留、截断单列、不自动重试。格式修复候选必须标记，不能自动通过。
- 服务重启会把未完成的图文调用标为中断，不自动重发。真实收费调用只由用户明确触发；失败后重新验收仍可能计费。

## 验证方式

后端测试覆盖真实图片解码、按序多图请求、跨任务引用、文件篡改、版本与规则失效、AI失败门禁、品牌退回/通过、幂等和归档。Windows使用UTF-8模式运行，避免现有测试按GBK读取UTF-8文件：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m pytest -c backend/pyproject.toml backend/tests
```

浏览器端完整图文流程使用**隔离测试服务里的固定模型输出**，不调用真实供应商，不修改开发数据库：

```powershell
$env:PATH = "$PWD\.venv\Scripts;" + $env:PATH
$env:PLAYWRIGHT_CHANNEL = 'chrome'
$env:E2E_IMAGE_MODEL_FIXTURE = '1'
npx playwright test e2e/image-post-workflow.spec.ts
```

固定输出只存在于 `scripts/e2e-backend.py` 的显式测试开关中，正常启动不会使用。流程与结构测试通过不证明真实模型的审核判断正确，真实模型/网关兼容性仍须通过用户显式发起的验收确认。


## 同屏验收布局

图文验收沿用脚本页的紧凑工作区：顶部集中切换类型、刷新和提交；左侧同屏展示当前配图、缩略图和标题正文，右侧独立滚动逐条反馈。总体意见与覆盖说明默认收起，版本和验收记录可在各栏顶部切换；品牌复核从顶部按钮打开抽屉。窄屏改为上下阅读，保留各栏独立滚动。

浏览器验证覆盖1366×768、1440×1080、1920×1080和390×844，以及保存、AI固定输出、品牌退回/通过、修改版失效和历史版本查看；未发起真实供应商调用。
