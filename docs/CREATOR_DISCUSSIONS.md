# 达人处理状态、逐条异议与站内催办

本功能用于脚本和视频，沿用当前本地／网关工作空间访问边界。不新增模型调用，不改写原始 AI 报告。现有演示角色切换不是独立账号鉴权；正式账号权限仍需另行接入。

## 达人入口

「我的合作」按项目卡展示脚本、视频和图文的真实提交时间与处理状态。合作进度总计两项：脚本＋成片，成片可选视频或图文，任一形式提交品牌即计一项；同时提交两种仍只计一项。未选择的成片形式不算缺交，入口保留可选。仅上传或 AI 验收完成尚未提交品牌时，不计为已提交；脚本和任一成片获品牌批准后显示完成。

在未通过／待确定的有效审核反馈中，达人可选择「收到，我去修改」或「我对 AI 有异议」。前者保存当次审核的修改状态；后者展示逐条异议入口。填写具体理由和可选的原文／视频位置后提交，才形成品牌可处理的异议。

脚本审核完成且没有任何未通过规则时，改为「提交品牌」和「我对 AI 有异议」，不再要求达人修改。正式提交绑定当前审核和脚本版本，保存后显示「已提交品牌」，刷新后保留；不重调模型、不新增脚本版本、不代替品牌批准。未点击提交时看板显示「待达人提交品牌」，点击后才显示待品牌确认并进入品牌审核队列；待确定项仍保留原判断，不能因提交而视为通过；已有异议优先显示有异议。脚本的通过项也可在选择异议后逐条说明。无效、修复待核对、历史失效报告不能正式提交。

同一任务、验收类型、审核记录、规则只有一个讨论线程。品牌要求补充后，达人可在原线程补充；采纳或驳回后线程保留只读。达人选择去修改不会静默删除已提交的异议。调用失败不能认定内容违规，也不能为无效报告虚构规则异议。

视频页的处理按钮位于右侧「整体结论」下方，使用金色按钮。选择「我对 AI 有异议」后展示「重新识别」，逐条异议入口仍在对应规则后。重新识别复用当前报告绑定的原视频和压缩档位，按当前模型配置、已保存规则新建审核；需要确认可能产生费用，不自动重试。旧报告、已提交异议及裁决保留，不自动转移到新审核。历史失效记录和正在审核中的记录不能从该入口重复提交。

脚本验收页使用三栏：左侧解析预览，中间按未通过／待确定／建议／通过／不适用查看结果，右侧显示材料信息、计数和底部操作。未通过默认展示；条件未触发的规则显示不适用，不阻断验收。

品牌脚本复核页复用同一套三栏预览、结果、计数与响应式栏宽，右下角替换为「审核通过」和「让达人继续修改」。通过保存品牌确认；退回先展开「达人修改要求」，必须填写内容后才能确认退回。修改要求记录在品牌决定中，达人在同一脚本页可看到。视频页右下角复用这两个操作；旧版本视频不能误提交当前版本决定。待确定脚本允许退回说明要求，但必须项未通过时仍不能直接批准。

## 品牌入口

侧栏「达人反馈」进入 `/feedback`，包含：

- 达人进度看板：当前阶段，或分别查看脚本／视频；按状态、达人／项目搜索。
- 异议处理：默认显示待裁决、待补充；查看当时冻结规则、AI 意见、达人说明、原始材料及已有取证。
- 提交记录：每次脚本、视频、图文验收均独立保留，可按达人／项目、类型和结果查询，包含处理中、未通过、待确定、调用异常、满足验收及品牌决定；详情对应当时材料和规则，不因后续重提通过而覆盖。
- 历史未通过记录：保留原来的历史复盘入口。

「查看并裁决」进入独立复核页 `/projects/:projectId/review-disputes/:disputeId`。沿用达人提交页的左右对照布局：左侧展示异议绑定版本的脚本解析、Excel 原布局、图片或视频原片，右侧展示争议规则、AI 原始意见、双方留言和裁决表单；可切换查看本次全部冻结规则，有引文时可定位左侧原文。历史异议始终读取该次审核绑定的脚本版本，不取最新稿。页面可直接刷新，裁决后保留当前页并更新状态，顶部返回异议列表。

品牌审核队列与提交记录分开：脚本须报告完整、材料齐备、没有仍然不符合的必须项，并由达人点击「提交品牌」后才进入待审队列。待确定项可交品牌核对，但不改变必须项通过门禁；视频同样需要达人点击「提交品牌」，不能仅凭调用成功就进入；待确定项可以交品牌人工核对。建议项继续不阻断，品牌已采纳的异议按人工裁决后的有效结果计算。未通过、未完成、缺配置和调用异常留在提交记录中处理，异议由异议后台裁决。视频的待确定项仍按原有口径交人工核对，不能等同于明确未通过。

项目详情「项目达人与审核进度」还提供当前项目的看板入口。侧栏显示待处理异议数量。

品牌裁决有三种：采纳异议（本条人工认可）、维持原判、请达人补充说明。必须填写理由并确认核对材料。所有评论和裁决追加记录，带时间、双方类型和修订版本；并发操作基于 revision 校验，写入使用幂等键。

采纳只对绑定审核中的该条规则生效：脚本与视频的当前通过判断读取独立人工裁决；AI 报告、组件计算与原始证据不覆盖。不补齐缺失报告、未覆盖材料或未配置条件，不自动批准整份内容。内容仍须完成原来的品牌确认流程。

## 状态与版本

未提交、已提交待验收、AI 审核中、调用异常、未通过待达人处理、修改中、有异议、待品牌确认、品牌已通过。

脚本和视频分别计算状态，AI 通过不等于品牌通过。新内容／新规则不沿用旧审核上的修改承诺或异议资格。旧异议可查看及归档裁决，但不改变当前版本状态。归档项目与任务禁止新增评论、裁决和催办。

## 催办

品牌在看板选择达人和阶段，发送站内催办。达人在「我的合作」及对应脚本／视频页查看、点击「收到」标为已读；品牌可查看最近催办时间与已读情况。这是站内通知，不发送短信、邮件、微信或其他外部消息。

## 数据与验证

迁移 `W_0015_creator_discussions.sql` 新增 `review_responses`、`review_disputes`、`review_dispute_messages`、`creator_reminders`，不修改历史模型结果。

迁移 `W_0016_script_formal_submission.sql` 保留历史处理记录，增加仅限脚本的 `submitted` 处理状态。

后端 `test_creator_discussions.py` 使用固定响应，覆盖脚本／视频闭环、人工裁决门禁、版本失效、跨任务与规则引用校验、修订冲突、催办幂等及已读。浏览器测试需显式启用仅测试服务生效的固定响应：

```powershell
$env:PATH = "$PWD\.venv\Scripts;" + $env:PATH
$env:PLAYWRIGHT_CHANNEL = 'chrome'
$env:E2E_DISCUSSION_FIXTURE = '1'
npx playwright test e2e/creator-discussions.spec.ts --reporter=line
```

正常后端不读取这个测试开关，不提供伪造审核接口。测试只验证协作、状态和门禁逻辑，不证明 AI 判断准确性。

视频正式提交使用迁移 `W_0017_video_formal_submission.sql`，保留原有脚本、视频处理记录并允许视频保存 `submitted` 状态。提交校验当前版本、报告完整性、活动规则覆盖及必须项/组件结果；旧版本、未完成、缺配置和明确未通过必须项不能提交。点击不触发模型请求，原始待确定结论保留。
