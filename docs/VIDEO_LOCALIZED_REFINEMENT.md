# 两阶段视频验收

新发起的视频运行快照固定 `pipelineVersion=localized_refinement_v1` 及定位、精判提示词版本。历史快照没有该版本时继续沿用旧工具调用流程，不自动重审。模型配置、启动和轮询 API 保持原样，设置返回的 `maxModelRequests=null` 表示按实际批次数调用，不再承诺整次最多四次。

## 执行与合并

第一轮完整音视频输入，强制调用 `submit_localization` 结构化返回每条规则的初判、范围覆盖声明、数字秒数窗口及组件观察。代码校验规则引用和时间；错误窗口不夹到合法范围、不猜测修补，对应规则待确认。全片缺失及无定位项沿用首轮判断并注明未精判，不捏造媒体证据。

定位问题与不确定窗口前后各补2秒，重叠区间合并。连续区间按30秒以内拆分，相邻重叠2秒；每批一个有声原片裁剪，所有相关规则一起复核。独立请求只含该段、相关规则、必要脚本和参考图、中性任务及原片偏移，不重复发送整片和首轮判定。临时上传协议按批上传对应片段，不保存临时地址或凭证。

精判通过 `submit_refinement` 返回片段相对时间，服务端换算原片时间。确认任一具体违规则不符合；候选全部排除且首轮完整覆盖则通过；失败、缺项、时间错误或仍不确定则保留待确认。单批失败继续剩余批次，不重试可能已计费的请求。最终汇总由代码生成，不增加一次总结模型调用。

组件首轮观察暂存；完整精判覆盖的区间替换原观察，该区间外的观察保留。原片时间统一后由现有组件计算时长、次数、交集与组合结果。量化规则缺少整片检查范围覆盖声明时不得通过。覆盖声明仍属于模型自报，不标记独立视觉检测已验证。

内部精判裁片不占历史展示证据的60件上限；最终问题与通过项均保留对应片段，多条规则可共享。首轮通过项使用模型定位的支持区间直接从原片裁片，不进入精判、不增加模型调用；精判后通过项复用已裁出的复核片段。全片未发现禁用内容等通过项保留检查范围记录，不随意取一段代替全片证明；无法定位或裁片失败明确展示说明，不伪造证据。

## 持久化和页面

结果增加 `pipeline`（阶段、初判、批次进度、原片映射和最终采用依据）及 `stageCalls`（阶段、请求ID、用量、耗时、提交状态）。每次返回先保留脱敏原始回复，再解析。原片视频和发送正文不写入诊断；失败和超时同样保留已有结果。服务重启标记运行及未完成批次中断，已完成批次与回复保留，不自动提交收费请求。

页面显示整片定位、裁片准备、精判X/Y、完成和累计计时；详情可查看初判/最终差异和每批状态。结果按未通过、待确定、已通过、全部、仅参考分类，默认未通过；没有未通过项时显示空态，不自动切换其他分类。必须项统一参与原有门禁，建议项不阻断。结构、时间与计算检查不代表模型判断准确；真实案例需人工对照评估。

## 验证

`test_localized_video.py` 覆盖裁片合并/拆分、误报撤销、多规则共享、未知区间、失败批次、超过4次调用、原片时间换算和组件计算。`test_evidence_console.py` 使用固定 HTTP 响应及本地生成音视频验证持久化、下载、失败和重启。浏览器用例 `video-localized-refinement.spec.ts` 验证进度、诊断、计时及历史显示，均不发起真实计费调用。
