# 品牌审核工作流第一版

本次把实际业务串为固定组件流程，不提供任意拖拽编辑器，也不包含发布。

## 操作路径

1. 在项目详情的「品牌内容审核工作流」进入 Brief 管理。沿用已有文件解析、要求编辑、来源定位、确认和启用功能。要求的 reviewStages 决定脚本/视频检查阶段。
2. 新建达人任务并绑定已启用规则，进入脚本页。粘贴脚本或上传 TXT/XLSX/DOCX，形成不可变版本。
3. 点击「开始 AI 脚本审核」，确认后使用设置中保存的服务地址、模型和加密 Key 发起一次真实文本请求。模型逐条检查适用于脚本的规则，给出原文引用、建议结论、理由与修改建议；引用必须是脚本真实子串。
4. 品牌核对脚本、Brief、AI建议及解析遗漏后，填写意见并确认通过或退回。AI结论不自动通过；品牌可说明理由后覆盖AI建议。通过当前脚本后可交达人拍摄。
5. 视频页使用完整音视频副本，不裁短或抽帧替代审核。模型同时收到冻结的视频阶段规则及已通过脚本，附加脚本执行一致性检查。每条规则附有服务器生成的取证策略：优先截图/有声片段、语境要求和工具预算。
6. AI分析成功后进入人工待办。品牌播放完整原片、核对依据及取证后，填写最终决定。通过更新任务为审核完成；退回保留原脚本通过资格，等待新视频审核。

## 当前性与历史

- 每次脚本审核冻结脚本版本、规则版本、模型配置、规则原文及来源；视频额外冻结脚本品牌确认记录ID和已通过脚本文本。
- 上下文指纹包含当前脚本、规则版本、平台、活动阶段、内容形式及最新失效事件。新脚本、活动阶段修改、规则换绑（包括换回旧版本）均不能复用旧通过记录。
- 开始新的当前脚本AI审核会回到脚本阶段；旧审核与决定继续可读。当前脚本解析失败时不审核，不拿旧的可解析脚本顶替。
- 视频绑定具体脚本确认记录，重新确认脚本后旧视频不能继续作最终决定。只有最新视频成功、且输入仍匹配时才能最终确认。
- 脚本真实调用和品牌决定均要求幂等键。网络失败不自动重发；服务重启将未终结脚本请求标为待核实。不得把遗留 processing 请求重新发送。

## API

- GET /api/v1/tasks/{taskId}/workflow
- POST /api/v1/tasks/{taskId}/workflow/script-reviews
- POST /api/v1/tasks/{taskId}/workflow/decisions
- GET /api/v1/workflow/review-queue
- 视频继续使用 evidence-runs；有 taskId 时必须经服务器校验脚本通过资格，独立设置页测试不改变任务状态。

## 第一版范围

本地品牌审核人统一身份，尚无多人账号权限。人工确认是品牌明确的业务决定，不代表模型已证明全片覆盖；每次请求最多4轮的视频取证预算沿用现有设置。脚本仅送提取的文本，图片等解析遗漏需要品牌人工核对。当前取证工具向模型返回证据元数据，没有将截图文件再次送入模型进行第二轮视觉验证。

项目详情和任务页提供固定流程、阶段标记、规则阶段及取证策略预览。后续可在此基础上开放组件参数和受约束分支，而不把品牌原文当成可执行代码。

## 验证

后端集成测试使用真实临时数据库、文件上传、FFmpeg完整音视频处理以及模拟模型HTTP，覆盖脚本→确认→视频→最终决定、新脚本失效、伪造引用拒绝、幂等回放和待办流转。浏览器测试模拟模型接口，覆盖操作流程，不发付费调用。
