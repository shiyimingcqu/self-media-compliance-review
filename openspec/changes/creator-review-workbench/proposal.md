# Proposal

## Why

达人投放的 Brief、脚本和成片分散在多种文件里，人工重复核对耗时，容易混用平台要求或丢失版本依据。需要把七张工作台设计图落实为可开发、可验收的 Web 产品规格，在一周 MVP 中验证完整视频审核与人工确认闭环。

## What Changes

- 建立项目列表和项目详情，按项目、平台、达人任务组织材料及审核进度。
- 建立 Brief 原文预览、规则拆解、适用范围、冲突处理与人工确认流程。
- 建立 Word/Excel/TXT 与粘贴文本脚本的审核、原文定位及版本对比。
- 建立完整视频和完整音轨审核、原视频播放、问题时间轴、脚本一致性检查。
- 建立人工待办、逐条问题裁决、人工补充问题、最终通过或退回及审计历史。
- 建立服务端模型配置、能力校验、演示/真实模式隔离与后台任务状态恢复。
- 统一七图的导航、状态和数据语义；移除发布流程，修正规则适用范围和示意模型能力。
- 提供页面详设、接口契约、验收场景和实施任务，作为后续编码依据。

## Capabilities

### New Capabilities

- `workbench-foundation`：公共布局、导航、可访问性、任务状态、版本与演示隔离。
- `project-list`：项目查询、统计、分页、新建和项目操作。
- `project-detail`：项目概览、平台筛选、Brief 绑定、达人任务创建及进度。
- `brief-requirements`：Brief 解析、规则编辑、来源定位、冲突处理与启用版本。
- `script-review`：脚本提交、证据定位、逐条审核、版本比较及视频阶段准入。
- `video-review`：完整视频任务、音轨检查、问题定位、报告与复核流转。
- `human-review`：待办筛选、复核草稿、问题裁决、人工最终决定和操作历史。
- `model-settings`：模型配置、密钥保护、连接及视频能力验证、运行模式与参数。

### Modified Capabilities

无。初始化时主规格清单为空。

## Impact

- 涉及七个前端页面、公共组件、后端文件处理、持久化、异步任务及模型适配器；技术方案见 design.md。
- 需要模型服务凭证及经过验证的完整视频输入能力。应用不提取离散帧代替视频输入；供应商内部采样不在应用控制范围。
- MVP 不包含星图/蒲公英/花火接入、自动发布、评论维护、多租户、复杂 RBAC 或多人实时编辑；人工审核人仍需有可追溯身份。
- 当前只提交规格，不创建应用、不调用收费审核服务、不把示意数据认定为真实结果。
