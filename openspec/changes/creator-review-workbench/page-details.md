# 七页面详细设计

状态：待实现的产品规格。参考图中的日期、数量、账号、商品素材和模型配置均为示意，不作为种子真实数据。除特别注明外，本文件数值为建议默认，可由服务端配置；规范行为见 specs。

## 0. 全局约定

### 0.1 公共框架

- 左侧固定导航：品牌标识、项目工作台、人工待办、模型设置。顶部显示当前本地审核人及演示模式标识；不开发无数据来源的通知铃铛。
- 主区：面包屑/返回、页面标题、说明、内容面板。复杂审核页显示任务上下文及统一流程步骤。
- 加载：首次显示骨架屏；后台刷新保留已有数据并标识正在更新；不以 0 伪装加载中的统计值。
- 错误：区分网络失败、权限/不存在、文件解析失败、模型失败、并发冲突；给出局部重试入口，保留用户输入。
- 表格：服务端分页，默认 10 条，可切换 20/50 条；默认更新时间降序，同时间用 ID 稳定排序。筛选更新返回第一页，URL 保存搜索、筛选、页码和排序。
- 搜索：300ms 防抖，清除立即生效；旧请求取消或忽略，避免慢响应覆盖新搜索。
- 表单：必填星号、字段旁错误、提交加载及防重复提交；取消不产生变更；离开未保存内容时提示保留或放弃。
- 时间：存储 UTC，界面按用户时区显示，默认 Asia/Hong_Kong；“较昨日”比较该时区两个相邻自然日，“较上周”比较相邻七天。
- 所有状态同时使用文字与颜色。空值使用“未提供/—”，不编造粉丝数量、头像或趋势。
- 演示与真实的页面、报告、历史均有模式标记；切换模式后查询范围同时切换。

### 0.2 七图一致性处理

图稿是组件与视觉参考，不代表所有面板同时展开。图 01 的弹窗、列表和空态分开呈现；图 03 的编辑及版本历史抽屉互斥；图 06 列表默认占主区，选择任务后右侧打开复核面板，独立路由可全宽打开。

页面 05 不增加全局导航项；统一用任务上下文进入。全站没有发布按钮或“完成发布”步骤。已有结果因版本变更失效时，使用“历史结果/依据已变更”的显式提示，不混入当前统计。

## 1. 项目列表页（01）

**路由**：`/projects`。**目标**：查询项目、识别待办规模、创建项目。

### 1.1 布局与组件

| 区域 | 组件 | 显示与交互 |
|---|---|---|
| 顶部 | PageHeader | “项目列表”、说明、“新建项目”主按钮 |
| 第一行 | StatCard × 3 | 进行中项目、待审核任务、待人工确认任务；趋势有历史数据才显示 |
| 第二行 | FilterBar | 项目名搜索、品牌、平台、状态、重置 |
| 主区 | ProjectTable | 项目、品牌、平台、达人任务数、完成进度、更新时间、状态、更多 |
| 底部 | Pagination | 总数、页码、每页条数 |
| 弹层 | CreateProjectModal | 新建和编辑项目表单；关闭后恢复触发按钮焦点 |
| 空态 | EmptyState | 首次无项目显示插画/说明/新建；筛选无结果显示“清除筛选” |

表格项目单元格包括封面缩略图、名称、截断说明。无封面使用统一占位图；点击名称进入项目详情。品牌为已存在品牌选择或输入新品牌，无须单独品牌管理页。平台显示多个徽标，不用“+2”隐藏关键平台；窄屏可 tooltip 展开。更多菜单包含编辑、归档/恢复归档；不提供永久删除。

### 1.2 字段与校验

| 字段 | 必填 | 默认/约束 |
|---|---|---|
| 项目名 | 是 | 去首尾空白后 1–50 字；同品牌同名不允许，返回字段错误 |
| 品牌 | 是 | 选择或新增，1–50 字 |
| 说明 | 否 | 最多 200 字，显示字数 |
| 投放平台 | 是 | 抖音/小红书/B站，至少一个；默认不预选 |
| 封面 | 否 | MVP 使用占位或已有素材，不要求开发独立图库 |

### 1.3 统计口径

- 进行中项目：当前模式、未归档且状态 active 的项目数。
- 待审核任务：当前未失效版本的脚本/视频作业处于 queued 或 processing 的达人任务数，同一达人任务只计一次。
- 待人工确认：当前有效复核处于 pending/draft 的任务数，包含正常与异常待办。
- 审核进度：人工最终通过任务数 / 项目未归档达人任务总数；0 个任务显示“尚无任务”，不显示 100%。百分比由分子分母计算并四舍五入，不硬编码图中的 75%。
- 顶部统计为当前模式全局值，不随表格筛选变化，并显示“全部项目统计”。

### 1.4 交互和边界

创建成功关闭弹窗并进入新项目详情；失败保留输入。筛选不改变已保存项目。归档前提示确认；有执行中作业时禁止归档，提示等待或处理作业。归档项目只读、从默认列表隐藏，可通过状态筛选恢复。项目全部任务通过后系统标 completed；新增任务后重新 active。

## 2. 项目详情页（02）

**路由**：`/projects/:projectId`。**目标**：管理平台 Brief、达人任务及审核阶段。

### 2.1 布局与组件

| 区域 | 组件 | 显示与交互 |
|---|---|---|
| 顶部 | Breadcrumb | 项目列表 / 当前项目 |
| 项目信息 | ProjectHeader | 封面、名称、品牌、说明、编辑 |
| 平台栏 | PlatformTabs | 全部及本项目平台；数字为对应未归档任务数 |
| Brief 区 | BriefOverviewList | 按 Brief/规则版本列出适用平台、阶段、文件大小、上传时间、确认状态 |
| 统计区 | StageStats | 待提交脚本、脚本需修改、待审核视频、待人工确认、已完成；补充“其他处理中”数量 |
| 任务区 | TaskFilterBar | 达人名、审核阶段、状态；平台由上方标签控制 |
| 任务区 | CreatorTaskTable | 达人、平台、绑定规则、脚本状态、视频状态、更新时间、操作 |
| 操作 | CreateTaskDrawer | 新建/修改达人任务 |
| 弹层 | HistoryDrawer | 文件提交、规则换绑、作业、人工决定时间线 |

Brief 可以有多份；图稿单张卡片不限制实际数量。只有一个 Brief 覆盖多平台时也必须保存每条规则的平台适用范围。无 Brief 时显示上传入口，允许先创建项目，不允许发起审核。

### 2.2 达人任务表单

| 字段 | 必填 | 校验/联动 |
|---|---|---|
| 达人名称 | 是 | 1–50 字，不以名称作为唯一 ID |
| 平台 | 是 | 仅可选项目已有平台 |
| 内容形式 | 是 | 视频/图文；本期完成视频闭环，图文禁用并标“后续支持” |
| 活动阶段 | 是 | 预热期/种草期/通用；默认通用，提交前用户明确确认 |
| 绑定 Brief 规则版本 | 是 | 仅列已启用、平台和阶段兼容的版本；没有时引导要求确认 |
| 主页链接 | 否 | 合法 HTTPS URL，仅作为资料，不自动抓取 |
| 头像/粉丝数 | 否 | 未提供则占位/—，不影响审核 |

同项目同平台同达人可以有多个独立合作任务，创建时提示可能重复，用户确认后继续。平台/阶段变更必须重新选择兼容规则。已产生提交后的改绑要展示失效影响并确认，服务端检查 revision。

### 2.3 导航与状态

“进入审核”根据当前阶段跳转脚本、视频或人工复核。点击规则版本进入对应只读规则快照；不是直接换绑控件。任务更多菜单保留进入审核、修改任务、查看历史。归档操作只在任务无运行中作业时允许。

阶段统计为当前平台下未归档任务的互斥分组：无脚本→待提交；当前脚本 changes_requested→需修改；脚本有效通过、人工待办尚未创建→待审核视频（包括未提交/待处理/需改视频）；存在当前有效待办→待人工确认；当前人工通过→完成。其余脚本处理中、规则失效等归为“其他处理中”，避免五个卡片暗示完整覆盖；点击卡片应用对应过滤。

项目编辑不得移除仍有任务或 Brief 规则使用的平台；提示先归档相关任务或保持平台。任务平台变化不得重写历史审核记录。

## 3. Brief 解析与要求确认页（03）

**路由**：`/projects/:projectId/briefs/:briefId`。**目标**：生成有来源、有适用范围、经人工确认的审核规则。

### 3.1 组件

| 区域 | 组件 | 行为 |
|---|---|---|
| 文件头 | BriefFileHeader | 文件名、格式、大小、页数（可得时）、平台、上传时间、解析状态、重新上传 |
| 左侧 | DocumentViewer | PDF 翻页/缩放/搜索/全屏；Word/TXT 展示保留段落的规范化预览及原件下载 |
| 左下 | SourceLocator | 按章节/页码/段落导航；不可得的定位方式禁用并说明 |
| 中上 | RuleStats | 总数、待确认、未解决冲突；单位统一为规则/冲突组 |
| 中部 | RuleFilter | 分类、多平台、内容形式、确认状态、关键词 |
| 中部 | RuleTable | 勾选、编号、要求、来源、适用范围、重要性、确认状态、更多 |
| 中下 | ConflictPanel | 冲突双方原文、位置、冲突原因、建议；编辑、缩小适用范围或停用一项 |
| 右侧 | RuleEditorDrawer | 添加/编辑要求 |
| 右侧互斥 | VersionHistoryDrawer | 版本、创建人、时间、变更摘要、查看只读历史 |
| 底栏 | StickyActionBar | 已选数量、批量确认、添加要求、保存草稿、确认并启用 |

### 3.2 规则数据与编辑字段

| 字段 | 约束 |
|---|---|
| 要求内容 | 必填，1–500 字；一条只描述可独立检查的行为 |
| 类别 | 必填：产品事实/卖点/画面/口播/字幕/禁用表达/发布材料/其他 |
| 适用平台 | 至少一个，限项目平台 |
| 内容形式 | 视频/图片图文/通用，不把“4 张”转换成视频露出次数 |
| 活动阶段 | 预热/种草/通用；支持日期范围辅助说明 |
| 检查阶段 | 脚本/视频/人工，可多选；只有画面结果的规则不能在脚本阶段判已执行 |
| 重要性 | 必须/建议，互斥单选 |
| 来源 | 文档页码、段落及原文引用；手动添加填写“品牌补充”及说明 |
| 例外条件 | 可选，最多 300 字，如“横测除外” |
| 确认状态 | 待确认/已确认/停用，冲突是独立标记 |

文档解析结果先区分产品事实、硬性要求、建议、创意示例和发布后事项。创意示例不默认生成强制规则；发布后评论维护可显示为范围外记录，不进入视频通过门禁。批量确认仅作用于已选、无未解决冲突且字段完整的规则；返回确认成功与未处理数量。

### 3.3 文件处理

接受 PDF/DOC/DOCX/TXT，建议上限 20MiB，服务端验证扩展名、签名、大小和可解析性。扫描件缺少文字时需要 OCR；未配置 OCR 显示“需要 OCR/请提交可读版本”，不得“解析完成但 0 条规则”。加密/损坏/旧格式转换失败保留原文件并提供重试/替换。源文件含图片但未理解时列出未覆盖页，并要求人工检查。

### 3.4 版本与启用

重新上传创建源文件新版本，不覆盖旧稿。保存草稿不改当前启用版本。点击确认启用时展示差异摘要、启用范围、未解决项；有待确认规则、未解决冲突、解析不完整或没有适用必须项时阻止启用并定位原因。人工可以对扫描页完成补录并签署覆盖确认，从而解决解析不完整；不能简单隐藏警告。

启用后规则不可原地修改，后续编辑产生草稿并在确认后生成新快照。已绑定旧规则的任务不自动迁移；显式换绑要提示重新审核。待启用版本编号由服务端生成，前端不根据图里的 v3.0 自行递增。

### 3.5 样例必须能表达的情况

- 小红书第 20 页禁止功效表达，不能因为抖音策略页出现“提神醒脑”就解除限制。
- 15 秒完整露出与 30 秒至少一次并存时展示冲突/重叠，交由品牌确认最终规则。
- “不少于 4 张”限制为图片要求；“Live 图至少一个”待确认交付范围。
- 阶段标签分别保存；不把预热与种草 TAG 合并为全部必带。

## 4. 脚本审核页（04）

**路由**：`/projects/:projectId/tasks/:taskId/script`。**目标**：解释问题、追溯依据、完成脚本版本审核。

### 4.1 组件

| 区域 | 组件 | 行为 |
|---|---|---|
| 顶部 | TaskContext | 项目、达人、平台、活动阶段、绑定规则；规则变更走显式操作 |
| 流程 | WorkflowStepper | 要求确认/脚本审核/视频审核/人工确认；历史节点可查看，不绕过准入 |
| 左上 | ScriptInputTabs | 上传文件/粘贴文本；一个提交版本采用一种输入方式 |
| 左侧 | ScriptPreview | 段落、表格、sheet/cell；点击问题高亮并滚动定位 |
| 左上操作 | VersionPicker/VersionDiff | 版本管理、双栏差异；区分新增/删除，Excel 按单元格位置 |
| 右上 | ReviewSummary | 符合、不符合、待确认、不适用的规则数及总数 |
| 右侧 | ResultFilter | 全部规则/需修改/待确认/已符合/不适用；类别过滤 |
| 右侧 | IssueCard | 结论、分类、规则 ID、脚本证据、Brief 依据、建议、待确认原因 |
| 底栏 | ActionBar | 已选文件、导出反馈、提交新版本、开始审核、进入视频审核 |

### 4.2 提交规则

上传支持 DOC/DOCX/XLS/XLSX/TXT；建议上限 20MiB。粘贴文本 1–50,000 字。文件名和 MIME/签名不一致时拒绝或提示转换，不只信任文件名。TXT 处理 UTF-8/常见中文编码，无法可靠解码时让用户重新提交 UTF-8。

表格预览保留工作表名、行列标题、合并单元格及文本；WPS DISPIMG/嵌图保留占位及原件定位，无法识别的内容提示人工核对。公式不执行任意宏或外链。旧 DOC 读取失败提示转换，不能误称 DOCX 已成功解析。

上传/粘贴后先形成不可变提交版本。AI 只能审核已解析且绑定规则有效的版本。没有确认规则时开始按钮禁用并链接 Brief。执行中禁用重复开始，对同一幂等键返回现有作业。

### 4.3 结果语义与导航

摘要以一条规则一个结果计数，多个问题可关联同一规则。列表注明“规则数”和“问题数”，不得用六张问题卡解释成十二条规则已全部显示。切换“全部规则”可查看每一条返回结果。

“提提神”和“喝完立刻精神”的剧情需要联合分析；“先说不好喝再反转”保留前后语境；脚本无镜头时长应判无法确认 15 秒要求，而非捏造超时证据。视觉质量只能审查拍摄计划，实际执行留到视频阶段。

开始后显示队列/进度，刷新恢复。模型返回缺项、空证据、非法规则 ID 或无效结构时显示不完整/失败，不自动通过。导出 Markdown/JSON 两种反馈，包含项目、达人、模式、脚本/规则版本、结论、证据和时间。

进入视频门禁：当前脚本 passed，或 needs_confirmation 的相关问题已由人工裁决并形成脚本阶段通过记录。需修改、未分析完、旧规则结果和演示结果用于真实任务时均阻止。新脚本使之前视频的脚本一致性依据失效，旧视频可保留但需重新审核。

## 5. 视频审核页（05）

**路由**：`/projects/:projectId/tasks/:taskId/video`。**目标**：完整视频审核、按时间定位反馈、衔接人工复核。

### 5.1 组件

| 区域 | 组件 | 行为 |
|---|---|---|
| 顶部 | TaskContext/VersionPicker | 项目达人、规则版本、脚本版本、视频版本、执行状态和 AI 结论 |
| 流程 | WorkflowStepper | 与脚本页共用，不包含发布 |
| 左上 | VideoUpload/Metadata | 上传或提交新版、文件名、时长、尺寸、音轨、大小、提交时间 |
| 左中 | JobProgress | 排队/上传供应商/处理/分析/完成；失败独立错误面板 |
| 左中 | VideoPlayer | 播放、暂停、进度、音量、静音、0.5/1/1.5/2 倍、全屏，兼容时启用画中画 |
| 左下 | IssueTimeline | 问题区间、当前游标、类别图例、重叠问题选择 |
| 中上 | VideoSummary | 当前问题数、待确认数、规则分析覆盖率、音视频处理状态 |
| 中部 | IssueList | 全部/画面/口播/字幕/脚本一致性；问题类型、区间、状态、规则与建议 |
| 右侧 | EvidencePanel | 当前规则、Brief 原文、已通过脚本、版本历史；可关闭 |
| 底栏 | ActionBar | 开始审核、重试、导出反馈、提交新版、进入人工复核 |

### 5.2 视频提交与完整性

允许 MP4/MOV/AVI 容器，但必须确认服务端可解码、播放器可播放及供应商可接收；不支持编码时提示无损容器转换/兼容转码并保留完整时序和原件。视频上限由能力接口给出，应用建议上限 2GiB；超过任一有效时长/大小限制时在开始前阻止。未验证的能力不能显示“≤60 分钟/500MB”。

服务端检查完整音视频时长、可解码性、轨道；无音轨时明确提示，并对口播相关规则判待确认/不完整。只有用户确认这是无口播创意、适用规则允许、并补齐人工核查时才可能继续；不能默认所有音频项不适用。原视频哈希记录到作业，完整原文件进入模型输入链路；不生成抽帧审核路径。

上传进度为真实字节比例；模型处理没有可观测百分比时显示阶段和耗时，不能假装精确 92%。正在运行时切版本只切查看对象，不中断后台作业；提交新版本不覆盖旧文件。

### 5.3 时间和证据联动

- 时间区间采用毫秒存储，展示 mm:ss，长视频展示 hh:mm:ss；满足 0 ≤ start < end ≤ duration。
- 点击问题卡或时间轴，从 start 前 2 秒（不小于 0）定位，选中该问题并同步依据面板；不强制自动播放。
- 到达 end 后不自动循环；用户可选择播放问题区间。播放器不支持定位时给出加载/重试状态。
- 多个重叠区间弹出问题列表，不能遮挡其他问题的点击入口。
- 问题缩略图不是审核依据必需项；MVP 使用同一视频封面占位，不通过后台抽帧生成审核证据。
- 时间无效的模型问题不能悄悄裁剪成有效值，应标记待定位/分析不完整，保留原输出用于诊断。

### 5.4 摘要、结果和流转

问题数按问题实体计数，待确认是其中子集，不与总数相加。覆盖率是有效返回适用规则结果的比例，绝不是准确率或通过率；鼠标及键盘聚焦提示公式。总览另外列出完整视频处理、完整音频处理、脚本一致性是否完成。

AI 通过不改变人工最终状态。passed/needs_confirmation 可创建待办；changes_requested 提示提交修改版，也允许因争议申请复核；incomplete/failed 创建异常待办，处理人可排障和退回，不能直接最终通过。

重试只对 failed/interrupted 的作业开放；running 禁用。供应商已接收但超时未知时先查询已有请求，不盲目重复收费。导出保留模式、供应商/模型、版本快照和证据，不能用导出动作改变状态。

## 6. 人工待办与复核页（06）

**路由**：`/reviews`、`/reviews/:reviewId`。**目标**：把 AI 分析转成可追溯的人工决定。

### 6.1 待办列表组件

| 组件 | 行为 |

| PageHeader | 人工待办与复核、任务说明 |

统计只覆盖 pending/draft，不包括已处理历史；历史通过独立状态筛选查看。归档任务不保留可提交的活动待办。当前图稿中的“发布于”统一改为提交于。

### 6.2 复核详情面板

### 6.3 字段、门禁及保存

问题处理理由建议必填 1–1000 字；确认问题会保留需修改状态，标记误判必须解释依据；暂不处理不算完成。人工添加问题必须有 0 ≤ start < end ≤ 视频时长，问题描述 1–1000 字，建议可选最多 1000 字。时间是视频时间输入器，不使用日期选择器。

最终决定无默认选项，必须主动选择。通过条件：当前完整真实分析有效、无未处理必须项、无确认成立的必须项问题、无未解决人工必须项、版本和 revision 未变。AI 待确认问题被有理由地裁决为符合后可通过；不能用“人工通过”覆盖缺失音轨分析或作业失败。退回必须有原因，至少引用问题或填写明确修改要求。

以上真实分析条件用于真实任务。演示空间可演练相同决定流程，但按钮及结果标“模拟通过/模拟退回”，记录 mode=demo，不产生真实任务的准入资格；模拟数据仍须遵守结构、版本和问题完整性门禁。

保存草稿只保存人工输入，待办保持 draft；取消可放弃本次未保存输入，不清除服务器草稿。最终提交使用事务和幂等键；连点只产生一次决定。如果另一个页面已提交新视频或换绑规则，返回冲突并显示新版本，保留可复制的旧草稿，禁止提交旧决定。

提交成功关闭/刷新列表；通过记为当前版本人工 approved，任务完成；退回为 returned，任务回到相应修改阶段，下一版重新审核。历史为追加记录，不能删除 AI 问题或改写过去决定。

## 7. 模型与运行设置页（07）

**路由**：`/settings/models`。**目标**：明确运行模式与实际可用能力。

### 7.1 组件

| 区域 | 组件 | 行为 |
|---|---|---|
| 页头 | PageHeader/ModeBanner | 当前已生效模式；草稿更改不提前改变横幅 |
| 左上 | ModelConfigForm | 服务商、接口地址、文本模型、视频模型/配置 |
| 左中 | SecretConfig | 是否已配置、掩码、替换/删除密钥、输入新密钥 |
| 左下 | ConnectionTest | 分别测试文本连接、完整视频输入、音轨能力，显示步骤、时间、错误 |
| 右上 | ModeSelector | 演示/真实审核单选，选择后需保存才生效 |
| 右中 | CapabilityCards | 音频、最大时长、大小、容器、验证状态、报告时间 |
| 右下 | RuntimeForm | 请求超时、并发、重试次数 |
| 底部 | SaveBar | 取消更改、保存配置，成功提示及生效范围 |

### 7.2 字段与校验

| 字段 | 约束/默认建议 |
|---|---|
| 服务商 | 豆包/火山引擎优先；只有已实现适配器可选，其他显示未接入 |
| 接口地址 | 必填，合法 HTTPS；后端禁止内网/元数据地址和非法重定向 |
| 文本模型 | 必填，服务端可用列表或手动 ID；未知 ID 需要连接验证 |
| 视频模型 | 必填；不能直接沿用任意文本模型下拉，完整视频能力需独立验证 |
| API 密钥 | 真实模式必需；未改密钥时不发送掩码作为新值 |
| 单请求超时 | 整数 30–1800 秒，建议 120；异步视频总作业时间与单请求超时分开处理 |
| 并发数 | 整数 1–10，建议 2；图中 5 仅示意，不保证供应商配额 |
| 自动重试 | 整数 0–3，建议 2；仅明确可安全重试的错误 |

用户输入新密钥时可点眼睛短暂查看尚未保存值；保存过的密钥不可取回明文。取消还原最后已保存配置。保存返回配置 revision，运行中作业保留原配置快照，新作业用新配置。

### 7.3 测试和模式

文本测试成功只证明文本接口连通，不把视频卡片设为绿色。完整视频测试必须提交测试完整视频并检测音轨分析结果，展示测试素材、供应商请求 ID、时间、能力及限制来源；缺证据显示未验证，不显示成功。

真实模式启用前需保存凭证、有效模型配置和通过的完整视频/音轨测试。若某适配器无音轨联合输入，必须验证全量音频补充链路。没有能力时仍可保存配置草稿、使用演示模式，不虚构接口支持。改变影响能力的模型/地址/服务商后，旧验证自动失效；仅修改并发不必重做能力验证。

演示模式不向真实模型发送业务文件，全部结果标模拟；新模式不重写运行中作业和历史报告的 mode。切换真实模式后模拟通过记录不能作为脚本/视频准入凭证。
